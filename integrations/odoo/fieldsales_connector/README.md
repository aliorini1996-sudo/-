# Field Sales Connector — وحدة Odoo

تستقبل ما يدفعه Field Sales (العملاء، المنتجات، الفواتير، السندات) وتُنشئ
ما يقابله في Odoo.

## ⚠️ حالة الوحدة — اقرأ قبل النشر

**الكود مكتوب ومُتحقَّق من صياغته وبنيته، ومنطق التخطيط مختبَر بـ٣٠ اختباراً
تمرّ. لكنّه لم يُثبَّت على خادم Odoo حيّ قطّ** — لا أملك تنصيباً لاختباره.
لذلك:

- **لا تنشرها على Odoo Apps قبل أن تُثبّتها وتُشغّل مزامنة حقيقية واحدة.**
  وحدة معطوبة في متجر Odoo تُنتج مراجعات سلبية دائمة يصعب محوها.
- ما هو **مضمون**: تركيب الحمولة، قواعد الترحيل، حساب الخصم، معالجة الصفوف
  التالفة، رفض الحمولات المشوّهة — كلّها مُغطّاة باختبارات تعمل بلا Odoo.
- ما هو **غير مُختبَر**: استدعاءات Odoo نفسها (`create`/`write`/`search`)،
  توارث شاشة الإعدادات، أسماء الحقول في Odoo 17 مقابل 18، تسجيل المسار.

### كيف تختبرها في ٢٠ دقيقة

```bash
docker run -d --name odoo-test -p 8069:8069 odoo:17
```

انسخ مجلّد `fieldsales_connector` إلى `addons/`، فعّل وضع المطوّر، حدّث قائمة
التطبيقات، ثبّت الوحدة، ثم:

```bash
curl -X POST http://localhost:8069/fieldsales/sync \
  -H "X-API-Key: المفتاح-من-الإعدادات" \
  -H "Content-Type: application/json" \
  -d '{"source":"field-sales","resource":"customers","count":1,
       "data":[{"id":"t1","code":"C-1","name":"عميل تجربة","phone":"05"}]}'
```

يجب أن يعود `{"ok": true, "created": 1, ...}` وأن يظهر العميل في Odoo.
شغّل الاختبارات المحلّية أولاً:

```bash
python integrations/odoo/fieldsales_connector/test_mapping.py
```

## ما تفعله الوحدة

| مورد Field Sales | نموذج Odoo | السلوك |
|---|---|---|
| العملاء | `res.partner` | upsert بـ`fs_id` |
| المنتجات | `product.template` | upsert بـ`fs_id` |
| الفواتير | `account.move` | **مسودّة فقط** |
| السندات | `fieldsales.receipt` | سجلّ للمراجعة |

## ما لا تفعله عمداً

هذه ليست نواقص بل قرارات:

1. **لا تُرحّل فاتورة (post).** الترحيل يُنشئ قيوداً محاسبية لا تُلغى إلا
   بعكس قيد. القرار للمحاسب لا لمزامنة آلية تعمل كل ساعة.
2. **لا تُنشئ دفعات.** الدفعة تحتاج دفتر يومية وحساباً وسيطاً، واختيارهما
   آلياً يضع القيود في حسابات خاطئة يصعب تتبّعها بعد أشهر.
3. **لا تنسخ أرصدة العملاء ولا مبيعاتهم التراكمية.** Odoo يحسبها من قيوده،
   فنسخها يُنتج رقمين متضاربين لنفس العميل.
4. **لا تُحدّث فاتورة مُرحَّلة.** إن رحّلها المحاسب ثم أُعيدت المزامنة،
   تُتخطّى ويُسجَّل ذلك — لا تُكتب فوق الدفاتر.
5. **لا تُخمّن ضريبة.** تُطابَق ضريبة البيع بالنسبة الرقمية؛ إن لم توجد
   نسبة مطابقة يُترك البند بلا ضريبة ويبقى الإجمالي الأصلي في `fs_total`
   للمقارنة. اختيار ضريبة «قريبة» يُنتج فروقاً صامتة في الإقرار.

## الإعداد

1. ثبّت الوحدة.
2. **الإعدادات ← عام ← Field Sales Connector**: ولّد مفتاحاً وانسخه.
3. في Field Sales: **الإعدادات ← ربط ERP** — المزوّد `ODOO`، الرابط
   `https://نطاقك/fieldsales/sync`، نوع المصادقة `API_KEY`، والصق المفتاح.

الترتيب مهمّ: **زامن العملاء والمنتجات قبل الفواتير.** الفاتورة التي لا
يوجد عميلها في Odoo تُرفض وتُسجَّل بسبب صريح بدل أن تُنشئ عميلاً مبتوراً.

## الأمان

- المسار عامّ لأن المُرسِل خادم لا مستخدم مسجَّل، فالمفتاح هو البوّابة
  الوحيدة. يُقارَن بـ`hmac.compare_digest` لا بـ`==`: المقارنة العادية
  تنتهي عند أوّل حرف مختلف فيتسرّب طول المطابقة عبر زمن الاستجابة.
- مفتاح غير مضبوط ⇒ ٥٠٣ لا قبول. وحدة غير مهيّأة يجب ألّا تكون نقطة كتابة
  مفتوحة.
- سقف حجم الحمولة ١٢ ميغابايت.
- تجديد المفتاح يُبطل القديم — حدّث Field Sales بعده.
